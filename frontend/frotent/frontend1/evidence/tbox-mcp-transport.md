## 3. 结论：为什么必须再挂一层 HTTP 传输

「自部署 MCP」下**只开放 `sse` 与 `streamableHttp` 两种连接方式，没有 stdio 选项**。这两种都是服务端可寻址的 HTTP 型传输，平台需要能主动访问一个 URL，无法让平台在本机 spawn 子进程，因此：

- 本地开发 / LiveAgent 宿主走 `mcp/stdio.ts`（stdio，宿主可 spawn）；
- 云端百宝箱必须走 `mcp/http.ts`（streamableHttp，默认 `http://127.0.0.1:8787/mcp`）。

两条链路共用同一个 `createCareerGraphServer(store)`、同一份版本化导出与同一套纯函数，只有传输层不同 —— 三个工具的名字、schema、返回结构逐字相同（见 `mcp/http.ts:1-18` 的说明）。

## 4. 与待提交表单草稿的对应关系

平台侧「待提交表单草稿」应按本节实测字段填写：

- 插件名称 / 插件描述：分别不超过 30 / 600 字符；
- MCP 创建方式 = `自部署 MCP`；
- 连接方式 = `streamableHttp`；
- 输入 MCP URL = `<稳定公网域名>/mcp`；
- Header 列表：留空（服务不校验自定义头）；
- 鉴权方式 = `不需要授权`。

## 5. URL 现状与遗留风险

2026-09-15 已把公网入口从随机域名（`legal-cloths-sink.loca.lt`）换成 **localtunnel 固定子域名 `https://careergraph-fuwuwaibao.loca.lt`**，并针对该地址重新生成了 `evidence/mcp-public-verify.json`（25/25 通过，failures 为空）。

需要注意两点：

1. **它仍是隧道，不是托管服务。** 地址本身固定，但承载进程一停就失效，平台侧调用会立刻全挂。终态应把 `mcp/http.ts` 部署到公网主机或用自有域名。
2. **机器客户端可直连。** localtunnel 的提示页只对浏览器式请求生效；实测 `curl` 默认 UA 与 `node` UA 直接拿到 JSON（200 `application/json`），无需 `bypass-tunnel-reminder` 头。所以平台侧的非浏览器 MCP 客户端不会被提示页挡住。
