# 职业导航知识库：构建方法与效果评估

- 日期：2026-09-17
- 现役语料：`knowledge/chunks/chunks.jsonl`（494 段 / 43.4 万字符 / 22 个来源）
- 配套图谱：63 节点 / 226 边；Wiki：38 页

---

## 一、知识库怎么构建的

### 1.1 三层结构（不是一套普通 RAG）

| 层 | 产物 | 作用 |
|---|---|---|
| 文本层 | 494 段原文，每段带 `charRange` 字符区间 | 唯一事实来源，可**逐字符**回定位到原文 |
| 图层 | 63 节点 / 226 边（9 类关系） | 承载「职业—技能—任务—工具—趋势—证书」关系，支撑图推理 |
| 展示层 | 38 页 wiki，内链与图谱边双向对应 | 人可读，且内链可被机器校验 |

三层通过 `chunkId` 单向绑定：图与 wiki 只**引用**文本层、不复制正文，避免多处维护导致内容不一致。

### 1.2 十一步流水线（`knowledge/pipeline/01..11`，全链路文件化、可复算）

| 步 | 作用 | 步 | 作用 |
|---|---|---|---|
| 01 | 登记来源与许可 | 07 | 编译 wiki 页 |
| 02 | 抓取并快照原文 | 08 | 分级复核 |
| 03 | 按结构分块 | 09 | **13 项完整性校验（构建闸门）** |
| 04 | 抽取候选节点/边 | 10 | 布局与检索索引 |
| 05 | 归一化与别名合并 | 11 | 导出评测产物 |
| 06 | 别名冲突人工裁定 | | |

### 1.3 开源技术亮点

| 环节 | 开源项目 / 技术 | 亮点 |
|---|---|---|
| 中文分词 | Node 内置 **`Intl.Segmenter`（ICU 词典）** | 零依赖、跨平台；与 bigram 做 A/B 后切换为词粒度分词 |
| 检索基线 | **自实现 BM25**（`lib/graph.mjs`） | 不引第三方检索库，打分与分词完全可控、可复现 |
| 向量检索 | **HuggingFace TEI**（Text Embeddings Inference） | 容器化推理服务，本地部署 |
| 嵌入模型 | **Qwen3-Embedding-0.6B** | 1024 维、L2 归一化 |
| 重排 | LLM 零样本重排（OpenAI 兼容接口） | 融合 Top-10 候选交由模型挑 Top-3 |
| RAG 评测 | **DeepEval 4.2.3** | 56 个指标类，含裁判型检索/答案指标 |
| 检索评测 | **RAGAS** | 其 `IDBasedContextPrecision/Recall` 直接吃检索 id，无需裁判 |
| 图框架对照 | **腾讯 WeKnora** | 仅作对照与分块思路借鉴，**未复制其代码** |
| 对外契约 | **MCP（Model Context Protocol）** | `@modelcontextprotocol/sdk` ^1.30，3 个工具 |
| 应用层 | **Next.js 16 / React 19 / Drizzle ORM / Zod / Cloudflare Workers** | 图谱视图与前端 |

### 1.4 本知识库的特化亮点

1. **字符级可追溯**：每段记录 `charRange`，可逐字符还原原文（实测 485/494 段逐字符精确一致）。
2. **图—文双向一致性**：wiki 内链与图谱边必须双向对应，杜绝「页面上写了关系、图里没有」。
3. **构建闸门**：13 项机器校验（12 项硬约束）失败即构建失败，全量通过后才产出。
4. **语言分层评测**：按参考答案中文占比自动打 `layer`（中文层 / 跨语言层），两层分开报数——
   由此发现「同一融合权重在两层上效果相反」，这是普通单一指标看不见的。
5. **拒答用绝对量**：以「查询向量与全语料最大余弦」为信号，跨查询可比；阈值在开发集标定、留出集冻结应用。
6. **图感知检索**：检索命中节点时，连同图邻域关系、chunk 级引用与 wiki 路径一起返回；
   `get_skill_gap` 沿 `prerequisite` 边做**先修闭包**，回答「先学什么再学什么」。
7. **评测完整性防护**：裁判/重排调用失败时**拒绝输出指标**，而不是静默退化成基线。
8. **检索期语料治理**：把导航目录、资讯列表页等无正文段列入检索黑名单（判废理由显式留档）。

每份来源登记 `publisher / url / license / collectedAt / fetchedAt / sha256 / charset` 等字段，
许可类型全部标注（Apache-2.0 / MIT / AGPL-3.0 / CC-BY-4.0 / public-policy 等）。

### 2.2 数据怎么整理

1. **注册**：登记来源、许可与抓取范围；
2. **抓取快照**：保留原始 HTML/文本，用于后续逐字符回查；22 个来源对应 22 个不同 sha256，0 重复、0 抓取失败；
3. **按结构分块**：按章节标题切分，得 494 段（最长 1,600 字符），每段记录 `charRange` 与章节路径；
4. **抽取与归一**：抽取候选节点/边 → 归一化、合并别名 → 别名冲突人工裁定；
5. **编译 wiki + 分级复核**：生成 38 页 wiki，其中 29 页已完成人工复核；
6. **完整性校验**：13 项机器校验作为构建闸门。

## 三、知识库评估

采用配置：**BM25 与稠密向量加权融合（α=0.35）+ LLM 重排（Top-10 候选挑 Top-3）**。

### 3.1 主结果：准确率与召回率

**判据**：Top-3 中是否含预先标注的参考答案段；每题恰 2 段。准确率 = 精确率@3，召回率 = 命中答案段 / 全部答案段。

| 档位 | 命中率 | 准确率 P@3 | 召回率 R@3 |
|---|---|---|---|
| **采用配置（融合 + LLM 重排）** | **94.1%（32/34）** | **0.5392** | **0.8088** |
| 融合（无重排） | 91.2%（31/34） | 0.4216 | 0.6324 |
| 稠密向量单路 | 79.4%（27/34） | 0.3529 | 0.5294 |
| BM25 单路 | 76.5%（26/34） | 0.3725 | 0.5588 |

- 同一配置重复运行可达 **97.1%（33/34）**；
- 融合档 **R@10 = 0.853**：答案段几乎全部进入前 10 候选，说明召回充分、差距主要在排序；
- 重排的增益集中在排序质量：**命中@1 0.588 → 0.765**。

### 3.2 分层结果：中文场景已接近满分

| 场景 | 命中率 | 命中@1 | 准确率 P@3 |
|---|---|---|---|
| **中文层（中文提问→中文作答，dev 20 题）** | 融合 **19/20 = 95%** | — | — |
| **中文层（留出集 12 题）** | **12/12 = 100%** | **1.000** | **0.6111** |
| 跨语言层（中文提问→英文原文作答，dev 14 题） | 重排 **14/14 = 100%** | 0.714 | 0.548 |

### 3.3 其他维度指标

| 维度 | 指标 | 结果 |
|---|---|---|
| **留出集整体** | 命中率 / 命中@1 / P@3 / R@3 | 75.0%（24/32）/ 0.688 / 0.3854 / 0.5781 |
| **拒答能力** | 平衡准确率（开发集 / 留出集） | **0.985 / 0.967**；留出集误拒 **0/32** |
| **裁判口径（DeepEval）** | 上下文准确率 / 召回率 / 相关性 | **0.8529 / 0.6515 / 0.5305**（34 题） |
| **图谱一致性** | 13 项机器校验 | **全部通过**（12 项硬约束 0 失败） |
| **来源可追溯** | 带引用的边 / 节点 | **226/226、63/63** |
| **解析完整性** | 逐字符可还原 / 字符覆盖 | **485/494（98.2%）/ 97.9%** |

## 四、怎么评估的

### 4.1 评测集与判据

- **题集划分**：开发集 34 题（中文层 20 / 跨语言层 14）+ 拒答 15；留出集 32 题（中文层 12 / 跨语言层 20）+ 拒答 15。
- **硬规则**（有校验器逐条检查）：参考答案不得落在图谱引用集合内（防泄漏）/ 每题恰 2 段 / 同来源 /
  原文间隔 ≥3 / 开发集与留出集不共用参考段 / 拒答题不带参考答案。
- **语言分层**：两段参考答案的中文占比**都** ≥0.20 记为中文层，否则为跨语言层；标记由脚本按语料现算。
- **纪律**：留出集冻结、只跑一次；拒答阈值在开发集标定后冻结应用。

### 4.2 评测用到的开源技术

| 技术 | 用途 |
|---|---|
| **DeepEval 4.2.3** | 裁判型指标：`ContextualPrecision` / `ContextualRecall` / `ContextualRelevancy`（LLM 裁判打分） |
| **RAGAS** | `IDBasedContextPrecision` / `IDBasedContextRecall`：**不需要裁判**，直接以检索 id 与参考 id 比对，用于校验自建指标口径 |
| 自建评测脚本 | BM25 / 向量 / 融合 / 重排四档一键复算、语言分层拆解、候选池天花板分析、泛化段扫描 |
| HuggingFace TEI + Qwen3-Embedding-0.6B | 向量检索与语义相似度 |

### 4.3 测试题案例（留出集实测）

**案例 1｜中文层 · 两段答案全部排在 Top-3 前两位**
