# 标注复核清单（2026-09-27）

## 为什么有这份文件

在「候选池 10 → 30」优化后，test 32 题从 21/32 提升到 **26/32（81.3%）**。对剩余 6 道失败题做诊断时发现：

- **只有 1 道是召回失败**（T20，答案在纯向量全排序第 118 名，属跨语言难例）
- **5 道是「重排损失」**（答案进了候选池但没被选中）

逐题核对这 5 道的**标注内容**后，发现 **4 道的参考答案段指向了与问题无关的段落**——模型选中的段落反而是真正的答案。
**也就是说：当前 81.3% 被标注错误低估，不是检索能力不足。**

## 复核结论（逐题）

### T05 —— **标注存疑**

- **问题**：使用 SPI Master 在 ESP32 上通过 GPIO matrix 连接从设备时，最高支持多少 MHz 的通信频率？如果频率不够用该怎么办？
- **标注参考答案**：
  - `S02#s41` — `esp_err_t spi_bus_add_device(spi_host_device_t host_id, const spi_device_interface_config_...` ← 函数签名
  - `S02#s41~6` — `wait -- Time to wait before the the bus is occupied by the device. Currently MUST set to p...` ← 结构体字段说明
  - 两段**都没有提到频率上限**
- **模型选中**：
  - `S02#s22` — GPIO 矩阵与 IO_MUX：信号可通过 GPIO 交换矩阵传输到任何其他可用管脚
  - `S02#s27` — MISO 管脚的设置时间是 SPI 时钟速度的限制因素
  - `S02#s27~2` — **频率限制表：`当主机驱动为 GPIO_MATRIX (25 ns) 时：输入延迟 (ns) … 频率限制 (MHz) 25 → 26.67`** ← 直接回答问题
- **判断**：标注段与问题无关；模型选中的段落含**真正的答案**（频率上限的具体数值）

### T10 —— **标注存疑**

- **问题**：给某个 IO 配内部上拉或下拉时要注意哪些坑：重复调用会怎样、有没有哪些引脚根本没有内部上下拉电阻？另外 gpio_hold 是做什么用的，开启后引脚还受不受后续配置改动影响？
- **标注参考答案**：
  - `S04#s78~3` — `esp_err_t gpio_input_enable(gpio_num_t gpio_num) Enable input for an IO.` ← 函数签名
  - `S04#s78~7` — `esp_err_t gpio_get_drive_capability(...)` ← 函数签名
  - 两段与「上下拉注意事项」「gpio_hold」均无关
- **模型选中**：`S04#s78~9` — **`For digital IO, this API takes effect only if the corresponding digital IO pad hold functi...`** ← 正是 gpio_hold 的作用与影响范围
- **判断**：标注段与问题无关

### T12 —— **标注存疑**

- **问题**：SPI 主机驱动里「排队交给中断去执行」和「轮询发送」这两类事务，在接口用法和并发限制上分别有什么讲究？各自有没有明确的使用禁忌？
- **标注参考答案**：
  - `S02#s41~2` — `ESP_ERR_INVALID_ARG if parameter is invalid / ESP_ERR_INVALID_STATE if device already is freed / ESP_OK on success` ← 错误码列表
  - `S02#s41~5` — `ticks_to_wait -- Ticks to wait until there's a returned item... 返回: ESP_ERR_INVALID_ARG...` ← 参数说明
  - 两段均未涉及两类事务的用法与禁忌
- **模型选中**：
  - `S02#s20` — **「为避免代码过于复杂，请一次只向单个设备发送一种类型的传输事务（中断或轮询）」** ← 正是使用禁忌
  - `S02#s11` — 中断传输事务：可加入队列，由 ISR 自动逐一发送
  - `S02#s12` — 轮询传输事务：不依赖中断，不断轮询状态位
- **判断**：标注段与问题无关；模型选中的三段**完整回答了问题**

### T13 —— **标注存疑**

- **问题**：从 SPI 事务结果接口取回结果时，对事务描述符的使用有什么约束、为什么？另外 SPI 主机频率上限意味着什么：超过上限之后会出现什么现象？
- **标注参考答案**：
  - `S02#s41~3` — `This routine will wait until a transaction to the given device successfully completed.` ← 函数行为说明
  - `S02#s41~7` — `dummy_o -- Address of dummy bits used output. Set to NULL if not needed.` ← 参数说明
  - 均未提及「描述符约束」
- **模型选中**：`S02#s42~3` — **`This structure describes one SPI transaction. The descriptor should not be modified until...`** ← 正是描述符的使用约束
- **判断**：标注段与问题无关

### T15 —— **标注正确，但参考段信息量低**

- **问题**：fixture 之间能不能互相引用、价值是什么？同一个 fixture 在 conftest 与测试文件里都被定义时哪一层生效？
- **标注参考答案**：`S13#s225`（"fixture functions can use other fixtures themselves. This contributes to a modular design" ← **正确对应**）、`S13#s231`（overriding fixtures 的示例开头 `Given the tests file structure is: tests/ conftest.py...` ← 对应但只是代码块开头）
- **判断**：标注方向正确，但 `S13#s231` 的可读信息量偏低；是否算合格需人工定
