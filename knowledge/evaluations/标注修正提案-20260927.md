## 1. 逐题提案

### T05 —— 问：SPI Master 通过 GPIO matrix 连从设备时最高支持多少 MHz？频率不够怎么办？

| | 段落 | 内容摘录 |
|---|---|---|
| 原标注 | `S02#s41`、`S02#s41~6` | `esp_err_t spi_bus_add_device(...)` 函数签名、`wait -- MUST set to portMAX_DELAY`（**与频率无关**）|
| **建议改为** | **`S02#s22`** | **「只要有一个信号通过 GPIO 交换矩阵传输…只能传输最大时钟频率为 **40 MHz** 的信号」；「如果需要高速运行 SPI，请使用专用的 IO_MUX 管脚」** ← 同时回答「最高多少」与「不够怎么办」 |
| | **`S02#s27~2`** | **「当主机驱动为 GPIO_MATRIX (25 ns) 时：输入延迟 (ns) … 频率限制 (MHz) 25 → 26.67」** ← 给出定量限制 |
| 原文依据 | `S02` 章节「使用驱动程序 > GPIO 矩阵与 IO_MUX 管脚」「时序影响因素」 |

### T10 —— 问：IO 配内部上下拉要注意什么？gpio_hold 做什么、开启后还受不受后续配置影响？

| | 段落 | 内容摘录 |
|---|---|---|
| 原标注 | `S04#s78~3`、`S04#s78~7` | `gpio_input_enable`、`gpio_get_drive_capability` 函数签名（**与上下拉/ hold 无关**）|
| **建议改为** | **`S04#s74`** | **「gpio_config() 是一个一体化的 API，可用于配置 I/O 模式、内部上拉/下拉电阻等管脚设置，包括那些被 USB PHY 复用的引脚」** ← 回答配置上下拉的入口与注意点 |
| | **`S04#s78~8`** | **「For ESP32/S2/C3/S3/C2, this function cannot be used to hold the state of a digital GPIO during Deep-sleep. Even if this function is enabled, the digital GPIO will be reset to its default state when the chip wakes up…」** ← 回答 hold 的作用边界 |
| 原文依据 | `S04` 章节「IO 管脚配置」「API 参考 - 普通 GPIO > Functions」 |

### T12 —— 问：中断事务与轮询事务在接口用法和并发限制上有什么讲究？有哪些使用禁忌？

| | 段落 | 内容摘录 |
|---|---|---|
| 原标注 | `S02#s41~2`、`S02#s41~5` | 错误码列表 `ESP_ERR_INVALID_ARG / ESP_OK on success`、`ticks_to_wait` 参数说明（**未涉及两类事务用法**）|
| **建议改为** | **`S02#s20`** | **「为避免代码过于复杂，请一次只向单个设备发送一种类型的传输事务（中断或轮询）…由于未完成的轮询传输事务将阻塞其他传输事务，请务必在 spi_device_polling_start() 之后调用 spi_device_polling_end()」** ← 正是使用禁忌与并发限制 |
| | **`S02#s12`** | 「轮询传输事务不依赖于中断…传输事务类型的缺点是在这些事务进行期间，CPU 将被占用而处于忙碌状态」← 两类事务的代价对比 |
| 原文依据 | `S02` 章节「使用驱动程序 > 向同一设备发送混合传输事务的注意事项」「SPI 传输事务 > 轮询传输事务」 |

### T15 —— 问：fixture 之间能不能互相引用、价值是什么？同一 fixture 在 conftest 与测试文件都有定义时哪层生效？
