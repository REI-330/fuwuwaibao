# 题集扩容记录（2026-09-17 第二轮）

本次目标：把验收尺子做准——原 `questions-test.json` 只有 21 题（1 题 = 4.8pp、Wilson 区间半宽约 ±20pp），
计划扩到 40 题，dev 一并补齐。**实际只扩到 test 32 / dev 34**，原因是语料容量，下面全部给实测数字。

## 1. 为什么扩不到 40 / 54：语料里没有足够的「中文答案」段

未被图谱引用、长度 ≥300 字符的剩余段共 345 段，按参考答案段的**中文占比**分桶：

| 中文占比 | 段数 |
|---|---|
| 0（纯英文） | 156 |
| 0–0.1 | 63 |
| 0.1–0.3 | 51 |
| 0.3–0.6 | 56 |
| 0.6–0.9 | 19 |
| **0.9–1（纯中文）** | **0** |

也就是说这份语料里**根本没有纯中文文档**：记作「中文源」的段落里，大量是
`esp_err_t spi_bus_initialize(spi_host_device_t host_id, ...)` 这类中文占比 0.01 的 API 正文。

要求「两段参考答案的中文占比都 ≥ 阈值」，且同来源、原文间隔 ≥3、未占用，可出题数为：

| 阈值 | ≥0.10 | **≥0.20** | ≥0.30 | ≥0.40 |
|---|---|---|---|---|
| 可出题 | 37 | **28** | 18 | 8 |

目标需要新增 53 题（test +19 / dev +34），**放不下**。故按实测上限执行，并把语言分层写进题集。

复算命令：

```bash
python knowledge/eval/pool_capacity.py --min-gap 3 --lang cjk   # 逐类目容量（已修正「已占用」口径）
```

> ⚠ 修正一处旧口径：`build_candidate_pool.py` 里写死的「已占用」只统计 `questions-v2.json` 的 28 段，
> 不含之后产出的 dev/test 的 82 段，会高估可用量。`pool_capacity.py` 是修正后的版本。

## 3. 语言分层口径（必须写清，否则数字对不上）

新版题集每题带三个字段，由 `assemble_questionsets.py` **按 chunks.jsonl 现算**，不手写：

- `layer`：`zh` = 两段参考答案的中文占比**都** ≥0.20；`xl` = 否则（跨语言层）。
- `minRefCjkRatio` / `meanRefCjkRatio`：两段里较小值 / 均值。

**同一件事，聚合方式不同结论差很多**——这是上一轮报告 §4.5 与本轮标记看似矛盾的原因：

| 集合 | 「参考答案几乎全英文（<10%）」按两段**取均值** | 按两段**取较小值** |
|---|---|---|
| 现役 dev(20) | 5/20 | 11/20 |
| 现役 test(21) | 15/21 | 19/21 |
| 新 dev(34) | 5/34 | 11/34 |
| 新 test(32) | 15/32 | 19/32 |

上一轮报告 §4.5 的 `dev 5/20、test 15/21` 是**取均值**口径；本轮 `layer` 标记用**取较小值**（更保守：
只有两段答案都够中文才算中文层）。两种都成立，但引用时必须带口径。

### 3.1 更正 §4.5 的一处解释

§4.5 把「dev 与 test 语言构成不同」写成**两套题集**的差异。按本次实测，根因在**语料本身**：
中文段本来就少（见 §1），所以 test 的 15/21 跨语言题不是出题偏好，而是容量所迫。
结论方向不变（两层不能混着比、必须分开报数），但归因要从「题集不同」改成「语料结构如此，
题集分层是必然结果」。

## 4. 人工判废的段（5 段，不再回收）

机械指标分不开「正文」与「导航/列表页」——实测散文度（含句读的行占比）对 `S07#4.2`
这种合法 API 列表也是 0.04，与导航目录同档；短行占比又把 `S21#s349`（政策类文档，0.92）
与导航目录混在一起。**这类判断只能靠读**，故判废理由显式记录在选段脚本参数里：

| 段 | 判废理由 |
|---|---|
| `S14#s278` | 导航目录（Home/Install/Contents/API Reference…）+ 章节标题清单，无正文 |
| `S21#s349` | 资讯门户首页导航（星计划/用户主页菜单/论坛入口）+ 文章标题列表 |
| `S21#s349~2` / `~4` / `~5` | 新闻摘要卡片列表，只有导语摘要 |

代价：`S14#s278` 出局使测试自动化少 1 题；`S21` 三段的出局使「标准与政策」类目新增容量归零
（`S19` 只剩 2 段可用，凑不出间隔 ≥3 的段对）。**该类目本轮 0 新增**，测试集里仍只有现役那 2 题职业能力。

## 5. 复算路径

```bash
# 容量核算（修正口径）
python knowledge/eval/pool_capacity.py --min-gap 3 --lang cjk

# 选段（判废理由随命令记录）
python knowledge/eval/plan_new_questions.py \
  --quota "dev:AI框架与推理=8,test:AI框架与推理=5,dev:测试自动化=4,test:测试自动化=4,dev:嵌入式开发=2,test:嵌入式开发=2,dev:标准与政策=1,test:标准与政策=1" \
  --min-cjk-ratio 0.2 --min-gap 3 --min-chars 300 \
  --reject "S14#s278:导航目录,S21#s349:门户首页导航,S21#s349~2:新闻摘要列表,S21#s349~4:新闻摘要列表,S21#s349~5:新闻摘要列表" \
  --out knowledge/evaluations/_plan-new.md --picks knowledge/evaluations/_picks-new.json

# 组装（合并新题 + 打语言分层标记）
python knowledge/eval/assemble_questionsets.py

# 校验（六条硬规则 + 跨集重叠）
python knowledge/eval/validate_questionset.py \
  --dev knowledge/evaluations/questions-dev.json \
  --test knowledge/evaluations/questions-test.json --min-gap 3
```

当前校验结果：dev 34 可回答 + 15 拒答、test 32 可回答 + 15 拒答；硬规则全部通过；dev/test 参考答案段无重叠。
