# 评测集划分方案（dev / test / 拒答）

- 版本：v1，2026-09-17
- 适用语料：`knowledge/chunks/chunks.jsonl`（494 段 / 22 来源）+ `knowledge/graph/graph.json`（63 节点 / 226 边）
- 配套脚本：`knowledge/eval/build_candidate_pool.py`（候选池与容量）、`knowledge/eval/validate_questionset.py`（校验器）

## 0. 为什么要划分：先承认现在的问题

**这套检索链路是零训练的**——BM25 是统计公式、向量用现成权重（Qwen3-Embedding-0.6B，未微调）、融合权重 α 是手调超参、
重排是通用 LLM 零样本提示。所以严格说**我们没有训练集**。

那这 14 题充当了什么角色？它同时是 **dev 和 test**：
α 的取值、候选池深度、以及「重排到底要不要上」都是在它上面选出来的，选完又用它报成绩。
这是典型的 **selection on the test set**，会系统性高估。

所以划分的目的不是"训练一个模型"，而是**让最终报出来的数字落在没被调参碰过的题上**。

| 集合 | 作用 | 纪律 |
|---|---|---|
| **dev（开发集）** | 选超参、试方案、跑负结果 | 可反复跑 |
| **test（测试集）** | 只出最终成绩 | **冻结**：不得用于任何调参／选型，只跑一次 |
| **拒答集** | 测"资料不足"的能力 | 拒答阈值是超参 → 需 dev 拒答集来调，test 拒答集只报数 |

- 现役 14 题**全部归 dev**：CV 3 题、标准与政策 1 题已经占满甚至超过小类目的 dev 配额，所以 CV 与政策类目基本不再新增 dev 题。
- **需新写 80 题**（dev 40 + test 40），消耗 160 段参考答案 ≤ 317 段剩余容量，余量充足。

### 2.1 test 为什么是 40 题

按配对设计（同一批题跑两档，McNemar，α=0.05、power=0.8）：

| 想分辨的差异 | 两档分歧率 10% | 分歧率 20% |
|---|---|---|
| 14pp（单路 → 融合，现役实测效应量） | 38 题 | 78 题 |
| 7pp（融合 → 重排） | 158 题 | 318 题 |

40 题是**能分辨 ≥14pp 差异**的最小可用规模。7pp 级别的结论（重排值不值）靠命中率仍然测不出，
要改用连续指标（Top-3 槽里的参考答案段数）或扩语料——**不要用题量去硬撑测不出的结论**。

## 3. 硬规则（校验器逐条检查）

| # | 规则 | 为什么 |
|---|---|---|
| R1 | 参考答案段**不得落在图谱 `sourceRefs` 引用集合内** | 旧主集 134 段 100% 落在引用集合内，任何"用图"策略都被泄漏抬高 |
| R2 | 每题**恰 2 段**参考答案 | 期望段数不一致会让不同集合不可比（旧主集均值 7.4 段 vs 留出集 1 段） |
| R3 | 两段参考答案在原文**间隔 ≥ 3** | 现役 14 题里 **10 题不满足**（7 题直接相邻），把邻域/窗口类技术的增益结构性放大了 |
| R4 | 两段**同来源** | 跨来源会让"来源级命中"的口径失真 |
| R5 | **dev / test 的参考答案段不得重叠**，题号不得重复 | 否则 test 不再是干净留出集 |
| R6 | 拒答题**不得带参考答案** | 口径自相矛盾 |

校验命令：

```bash
# 单集
python knowledge/eval/validate_questionset.py --set knowledge/evaluations/questions-v2.json --min-gap 3

# dev/test 两集（还会检查跨集重叠）
python knowledge/eval/validate_questionset.py \
  --dev knowledge/evaluations/questions-dev.json \
  --test knowledge/evaluations/questions-test.json --min-gap 3
```

现有 14 题的实测结果：R1 全过；**R3 有 10 题不通过**；R4、R2、R6 全过。

## 4. dev / test 隔离纪律

1. **test 冻结**：冻结后不得用于任何调参、选型、试错。任何一次用 test 比较两个方案，它就退化成 dev。
2. **报数只报 test**；dev 上的数字只能在报告里以"开发集"名义出现，并注明"该集合参与过选型"。
3. **test 只跑一次**：跑完即锁，产物带时间戳存档；模型/提示/参数任何改动都要在 dev 上定完再动 test。
4. **拒答阈值**同样在 dev 拒答集上调，test 拒答集只报数。
5. 题集文件拆成 `questions-dev.json` / `questions-test.json`，`questions-v2.json` 保留为 dev 的历史快照（已加 `split: "dev"` 标记）。
