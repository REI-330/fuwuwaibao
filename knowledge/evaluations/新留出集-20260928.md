## 怎么建的

1. **分片备料**（`build_material.py`）——每片导出 15–36 段候选段**全文**，预先排掉三类不可用段：
   - 已被 dev/test 当参考答案用过；
   - 落在图谱引用集合内（`validate_questionset.py` 的硬规则，会泄漏）；
   - **与已用段原文区间重叠**——语料是 ~1500 字重叠窗口，同一句话有多个 chunkId，
     不排掉就会挑到"同一段正文的两个窗口"。
2. **格点抽样**——按原文顺序取 `i % 6 ∈ {0, 3}` 两条交错格点，使同一来源内任意两段的
   顺序差都是 3 的倍数且 ≥3。
3. **分片起草**——5 片中文/英文各由独立起草人读原文出题（只看材料，不看旧题集）。
4. **两级校验**——`assemble_holdout.py`（合并 + 校验 + 统一重算 layer）与项目自带的
   `validate_questionset.py`，两者都通过才落盘。

## 过程中发现并修掉的两个 bug（都出在材料生成）

### 1. 来源偏置：前 N 个候选段全落在同一个来源

原先按 `(sourceId, sectionPath)` 排序取前 N 个小节。因为元组按 sourceId 先排，
前 N 个全落在字母序最前的来源上——实测 `xl-onet` 24 段**全是 S16、一个 S17 都没有**，
`xl-embedded` 只拿到 S02/S03。改成跨来源轮转后，S16/S17 各 10 段、S02–S12 五个来源都有。

### 2. 间隔判据错位：`candidates` 数组下标 ≠ 原文顺序

brief 原写"用数组下标差判间隔 ≥3"。但数组是**跨来源轮转拼出来的**，不等于原文顺序。
起草人照此核出"差 ≥3"，实际原文只差 1–2，**6 道题被打回**。
修法：材料里每段带上 `docIndex`（该来源内按原文顺序的位置），brief 明确要求用 `docIndex` 之差。

> 教训：**约束要写在材料里，不能只写在说明里**。格点抽样让"任意两段都合规"成立，
> 比"提醒起草人注意"可靠得多。

## 用法

```bash
set -a; . knowledge/eval/.env; set +a
export TEI_MODEL=Qwen3-Embedding-0.6B-onnx-int8 TEI_EMBED_URL=http://127.0.0.1:8090/v1/embeddings

# 1) 先出该题集的 BM25 完整排序（术语词典增强版；不加 --tag 会覆盖别的题集的产物）
python knowledge/eval/query_expansion_experiment.py \
  --questions knowledge/evaluations/questions-holdout.json \
  --bm25-baseline knowledge/eval/runs/q1024-holdout-bm25-full.json \
  --expand-with term-map --tag holdout-termmap --emit-only

# 2) 跑已采纳配置
.venv/Scripts/python.exe knowledge/eval/run_adopted.py \
  --questions knowledge/evaluations/questions-holdout.json --tag holdout- \
  --alpha 0.35 --do-rerank --rerank-candidates 30 \
  --rerank-cache knowledge/eval/runs/holdout-rerank-cache.json \
  --bm25 knowledge/eval/runs/bm25-full-expanded-holdout-termmap.json
```

⚠ 注意 `--bm25-baseline` 那个文件（`q1024-holdout-bm25-full.json`）要先用
`node knowledge/pipeline/bm25-full.mjs` 对本题集生成一次。

## 复跑方式

```bash
python knowledge/evaluations/holdout-build/build_material.py        # 重新分片备料
python knowledge/evaluations/holdout-build/assemble_holdout.py      # 合并 + 校验（--check 只校验）
python knowledge/eval/validate_questionset.py --set knowledge/evaluations/questions-holdout.json
```

起草稿在 `holdout-build/draft-*.json`，改题直接改这些再重跑 assemble。

## 已知限制（写报告时必须带上）

- 参考答案段的**精确 chunkId 口径会系统性低估命中**：语料是重叠窗口，同一句话有多个
  chunkId。详见 `project-career-graph-chunkid-metric-brittleness` 那条记忆与
  `标注修正执行记录-20260928.md` §5。
- 中文层（zh）只有 14 题，xl 层 21 题；两层的最优检索通道方向相反，报总分会把效应盖住，
  **必须分层报**。
- 本集尚未跑过任何配置，**没有任何基线数字**。第一次跑就是它的第一次消费。
