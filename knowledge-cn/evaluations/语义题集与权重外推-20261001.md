# 偏语义改写题集与 RRF 权重外推（2026-10-01）

> 这份报告回答一个此前**明确留白**的问题：「现役 RRF 权重 0.2/0.8 是在字面型题集上选出来的，
> 它是否也适合语义型问题？」（见 `检索质量评测-20261001.md` §十一 未做项）

## 一、结论先说

**0.2/0.8 在语义型题上不翻车，但它不是全面最优 —— 指标之间出现了一个真实的取舍。**

| 题集 | 权重（向量/关键词） | 命中@1 | @3 | @5 | @10（窗口内） | MRR | 均秩 |
|---|---|---|---|---|---|---|---|
| **偏语义 16 题** | 0.7 / 0.3 | 11/16 | 12 | 13 | **15/16** | 0.7500 | 2.75 |
| 偏语义 16 题 | 0.5 / 0.5 | 11/16 | 12 | 13 | 15/16 | 0.7526 | 2.62 |
| 偏语义 16 题 | 0.3 / 0.7 | 12/16 | 12 | 14 | 14/16 | 0.7812 | 2.62 |
| 偏语义 16 题 | **0.2 / 0.8（现役）** | **12/16** | **13** | 14 | 14/16 | **0.7865** | 2.56 |
| 偏语义 16 题 | 0.1 / 0.9 | 12/16 | 13 | 14 | 14/16 | 0.7865 | 2.56 |
| 字面 26 题（对照） | 0.7 / 0.3 | 18/26 | 21 | 23 | 26/26 | 0.7776 | 2.12 |
| 字面 26 题（对照） | 0.3 / 0.7 | 18/26 | 22 | 24 | 26/26 | 0.7904 | 1.96 |
| 字面 26 题（对照） | **0.2 / 0.8（现役）** | **19/26** | **23** | 24 | 26/26 | **0.8193** | 1.85 |

读法：

1. **@1 与 MRR 上，关键词占大头（0.2/0.8）在两类题集里都最好**，而且字面题集上的数字
   （19/26 = 73.1%、MRR 0.819）与 `检索质量评测-20261001.md` 记录的第三版**逐字复现**。
2. **但 @10「窗口内」这一列，语义题上 0.7/0.3 反而多找回 1 题**（15 vs 14）。也就是说：
   向量通道对语义型问题确有独立贡献，只是它的贡献更多落在**榜单中段**（把证据捞进 k 条上下文里），
   而不是落在**头名**上。压到 0.1/0.9 也不会更差，但也不会更好 —— 0.1 与 0.2 两档在语义题上完全同分。
3. 所以「0.2/0.8 是否适合语义型问题」的答案是：**作为现役排序目标（头部精度）它是合适的；
   但若下游更在意「证据有没有进上下文」（@10），语义型问题上调高向量权重有边际收益**。
   这个取舍**没有**被此前任何一次评测量化过，是这次新测出来的。

## 二、题集是怎么保证「偏语义」的

`knowledge-cn/evaluations/questions-cn-semantic-v1.json`（16 题）由
`knowledge-cn/eval/make_semantic_questions.py` 从**基础题集**生成：

- **gold 一个字都不改**：锚点、来源、预期答案逐字沿用基础题集；
- **只改提问措辞**，且脚本逐题断言「改写后的题面里**不出现该题任何 gold 组的任何锚点**」，
  不满足就报错退出 —— 所以「题面拿不到字面优势」是**机器校验过的事实**，不是形容词；
- 原问法保留在 `literalQuestion` 字段里，便于人工对照；
- 输出文件里同时写明诚实边界：**gold 仍然是作者标注 + 机器复核出处，不是业主人工判定相关性**；
  没有做跨语言或口语化改写；16 题只够回答「会不会翻车」，不足以定权重。

再做一次出题硬门禁（gold 必须在真实库里找得到证据）：

```bash
python knowledge-cn/eval/verify_questions.py \
  --db knowledge-v1/weknora-src/data/weknora-cn.db \
  --questions knowledge-cn/evaluations/questions-cn-semantic-v1.json \
  --out knowledge-cn/evidence/questions-semantic-verified.json
# 实测：题集 16 题（可答 16 / 超范围 0），gold 组 17 个，问题 0 处，锚点跨度偏大的组 0 个
```

## 三、复算命令

```bash
# 现役库 id 见 knowledge-cn/evaluations/questions-cn-v1.json 的 kb.id
python knowledge-cn/eval/rrf_weight_experiment.py \
  --kb aacc4889-a347-44ea-9dd1-b60ec1917cbb \
  --questions knowledge-cn/evaluations/questions-cn-semantic-v1.json \
  --weights 0.7:0.3,0.5:0.5,0.3:0.7,0.2:0.8,0.1:0.9 \
  --out knowledge-cn/evidence/rrf-weight-sweep-semantic.json

# 对照：同一批权重在字面题集上（复现第三版数字）
python knowledge-cn/eval/rrf_weight_experiment.py \
  --kb aacc4889-a347-44ea-9dd1-b60ec1917cbb \
  --questions knowledge-cn/evaluations/questions-cn-v1.json \
  --weights 0.7:0.3,0.3:0.7,0.2:0.8 \
  --out knowledge-cn/evidence/rrf-weight-sweep-literal-control.json
```

两条命令都**不改动现役配置**：脚本默认扫完恢复扫描前的 `retrieval-config`
（本次扫描前 = 0.2/0.8，扫描后仍为 0.2/0.8，两次都是 HTTP 200 恢复成功）。

  得另建题集。
