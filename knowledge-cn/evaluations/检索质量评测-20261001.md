# 中国官方语料知识库 · 检索质量评测（2026-10-01，两版对照）

- 题集：`knowledge-cn/evaluations/questions-cn-v1.json`（33 题：可答 26 / 超范围 7，gold 组 35 个）
- 被测对象：WeKnora Lite 知识库 `aacc4889-a347-44ea-9dd1-b60ec1917cbb`
  - **第一版（改造前）**：6 份文档（含重复的 nbs-wages-2025.md）/ 2167 chunk
  - **第二版（改造后）**：5 份文档 / 2641 chunk（结构化目录一条记录一个 chunk）
- 真实接口：`POST /api/v1/knowledge-bases/{kb}/hybrid-search`，`match_count=10`、`skip_context_enrichment=true`
- 证据：`evidence/retrieval-quality-20261001.json`（第一版）、`evidence/retrieval-quality-20261001-v2.json`（第二版）、
  `evidence/questions-verified.json`（gold 复核，含锚点跨度）、`evidence/boilerplate-experiment.json`（出处样板对照实验）

## 一、口径

| 项 | 定义 |
|---|---|
| gold | 锚点字符串（如 `["低空经济与管理","020110TK"]`），不用 chunkId；不受分块与重复导入影响 |
| 判定(a) 块内 | 前 k 条里存在**一条** chunk 同时含该组全部锚点 |
| 判定(b) 窗口内 | 前 k 条**合起来**含该组全部锚点（RAG 的真实形态） |
| 命中@k | **每个** gold 组都到齐才算命中；定位次取「最后一组到齐」的名次，MRR 取倒数 |
| preview@1 | 第 1 条 chunk 的前 120 字里是否含全部锚点（`verify_import.py` 的 `topPreview` 口径） |
| 超范围题 | 不做命中判定，只量分数分布 |
| judgment 组 | 作者裁定的跨源关联，不进头部指标 |

题集分布：专业目录 8、薪资统计 8、职业大典 7、跨源综合 3、超范围 7。

## 三、改造到底改掉了什么（这些是确定的）

| 项 | 改造前 | 改造后 | 依据 |
|---|---|---|---|
| 结构化目录的 chunk 粒度 | 287 chunk，277 个装 3 条记录 | **862 chunk，一块一条记录** | `evidence/recall-diagnosis-lowaltitude-v2.json` 的 `corpusShape` |
| 「记录排在 chunk 首条」的比例 | 287 / 850 = 33.8% | **850 / 850 = 100%** | 同上 |
| 重复文档 | `nbs-wages-2025.md` 两份（36+36 chunk、哈希序列一致） | **1 份**（软删除旧文档后重导） | `evidence/import-verify.json` 的 `chunksPerDocument` |
| 导入幂等 | 无闸门，重跑即堆重复 | 同名默认拒绝，`--replace` 才覆盖 | `acquisition/import_weknora.py` |
| 活检索探针 | 前 120 字显示邻座记录（「低空经济与管理」被看成「经济工程」） | 预览即目标记录，`topRecordIds` 只 1 条 | `evidence/import-verify.json` 的 `probe` |
| 核验脚本口径 | 未排软删除，重建后会虚高 | `JOIN knowledges ON deleted_at IS NULL` | `verify_import.py` |

## 四、改造没有带来什么（必须一起说）

1. **整体位次没有变好。** 全 26 题均秩 2.77 → 2.85，未换 gold 的 23 题 2.87 → 2.83（基本持平）；
   @1 命中数 14/23 → 12/23。
2. **@1 命中率掉了 11.5 个百分点**（16/26 → 13/26）。逐题看是有升有降：**升 6 题**
   （CN10 5→3、CN12 9→8、CN13 8→6、CN16 3→1、CN22 7→1、CN24 7→5），**降 4 题**
   （CN02 1→3、CN18 1→8、CN25 1→4、CN26 1→3），其余持平；另有 3 题（CN07 / CN08 / CN19）
   因**标注**从单组改成多组而变严（它们本来就是「代码与名称隔着 300+ 字」的跨块题）。
   26 题的样本量下，±4 题不足以支撑「改造让检索变差」的结论，但也**不能宣称变好**。
3. **@10 覆盖率两版都是 26/26**。也就是说这批语料从来不是「召不回来」，而是「排不准」。
4. **纯向量通道明显更弱**（@1 46.2% → 30.8%）。原因见下一节。

## 五、出处样板稀释假说：测了，不成立

改造后每个 151 字（中位）的 chunk 里，仍有 **58% 是同一段出处样板**
（`_出处：… · 类型：… · 记录 ID：… · 审核状态：… · 豁免人：业主_`）。怀疑它把 862 个 chunk 的向量
挤成一团、拖垮了向量通道。于是做了个**不动索引**的对照实验
（`eval/boilerplate_experiment.py`，用同一个 8090 嵌入服务分别算「带出处」与「剥掉出处」两套向量）：

| 指标 | 带出处 | 剥掉出处 |
|---|---|---|
| 862 个 chunk 的平均两两余弦 | 0.4902 | 0.4702 |
| 目标 chunk 名次改善 / 变差 / 不变 | — | **2 / 3 / 3** |

两点结论：

- 剥掉出处只把平均相似度从 0.49 降到 0.47 —— **相似不是样板造成的，是这批记录本身长得一样**
  （850 条 `专业代码：X／专业名称：Y／第 N 页` 的模板记录）。换渲染方式救不了向量通道。
- 名次有升有降（2 升 3 降），**没有系统性收益**。所以就**没有**再做一次「精简出处行」的重建
  —— 省下一轮十几分钟的导入，也避免把「改了个没用的东西」写进交付说明。

> 插一句：这个实验顺带确认了 8090 服务的 `model` 字段不影响结果（同一个文本用两个模型名，
> 返回向量完全相同），所以用任意模型名做对照实验是有效的。

## 六、两版都需要保留的结论

1. **关键词通道单独跑仍然优于混合**（第二版 @1 57.7% vs 50.0%，MRR 0.710 vs 0.632）。
   本题集偏字面事实（专业代码、表格数值、职业编码），关键词天然占优；**不能外推成「向量没用」**。
2. **超范围题在检索层完全分不出来。** 第二版 7 道超范围题的 top-1 分数**全部等于满分 0.016393**
   （两通道都排第 1），而可答题的 p25 是 0.016063 —— 按阈值判拒答 7/7 误判。拒答只能由上层
   依据「召回正文里有没有答案」来判断。
3. **弱项位置两版一致**：数值型表格题（行业工资排序，v2 仍在第 6–8 位）与跨源语义桥接
   （CN25/CN26 的 judgment 组两版都没进前 10）。
4. **不得对标 `docs/EVALUATION.md` 的「人工 100 题 Top-5 ≥ 80%」门槛**：本次是作者自出的
   26 道可答题、机器复核 gold，出题人与题量都不符。

## 八、复算方式

```bash
# 1) 标注门禁（35 个 gold 组必须在真实库里找到出处，并报出锚点跨度）
python knowledge-cn/eval/verify_questions.py \
  --db knowledge-v1/weknora-src/data/weknora-cn.db \
  --questions knowledge-cn/evaluations/questions-cn-v1.json \
  --out knowledge-cn/evidence/questions-verified.json

# 2) 三通道检索评测（块内 + 窗口内两个口径）
python knowledge-cn/eval/retrieval_quality.py \
  --kb aacc4889-a347-44ea-9dd1-b60ec1917cbb \
  --questions knowledge-cn/evaluations/questions-cn-v1.json \
  --top 10 --out knowledge-cn/evidence/retrieval-quality-<日期>.json

# 3) 出处样板对照实验（不动索引）
python knowledge-cn/eval/boilerplate_experiment.py \
  --db knowledge-v1/weknora-src/data/weknora-cn.db \
  --questions knowledge-cn/evaluations/questions-cn-v1.json \
  --out knowledge-cn/evidence/boilerplate-experiment.json

# 4) 整库重建（照表执行，可重复跑）
python knowledge-cn/acquisition/rebuild_weknora.py --kb-id <kb-id>
```

## 九、未做项（不得省略）

- 没有人工（业主）逐题复核 gold；gold 是作者标注 + 机器复核出处，不是人工判定相关性。
- 没有做「引用支持度 / 回答质量」评测（要调模型，属上层）。
- 没有做切块参数的网格搜索（只验证了「结构化目录 = heading + 200」这一组，依据是
  `/chunker/preview` 的 393/393 一块一条记录）。
- 没有做偏语义改写题集，所以 RRF 0.7/0.3 权重是否合适仍未定。
- 大典（1665 chunk）仍是默认 512 字切块，没有单独试过更小块。
