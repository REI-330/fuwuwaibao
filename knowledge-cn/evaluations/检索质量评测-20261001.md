# 中国官方语料知识库 · 检索质量评测（2026-10-01 首版）

- 题集：`knowledge-cn/evaluations/questions-cn-v1.json`（33 题：可答 26 / 超范围 7）
- 被测对象：WeKnora Lite 知识库 `aacc4889-a347-44ea-9dd1-b60ec1917cbb`（1519 条已审核记录 / 2167 chunk / 6 份文档）
- 真实接口：`POST /api/v1/knowledge-bases/{kb}/hybrid-search`，`match_count=10`、`skip_context_enrichment=true`
- 证据：`knowledge-cn/evidence/retrieval-quality-20261001.json`（逐题、逐通道、可复算）
- 出题标注复核：`knowledge-cn/evidence/questions-verified.json`（31 个 gold 组全部在真实库里找到出处，0 处问题）

## 一、口径（先说清楚在量什么）

| 项 | 定义 |
|---|---|
| gold | **锚点字符串**（如 `["低空经济与管理","020110TK"]`），不用 chunkId。512 字切块会把同一条记录切进不同 chunk，chunkId 口径会系统性误判；锚点在切块和重复导入下都稳定 |
| 命中@k | 前 k 条里，**每个 gold 组**都能找到一条同时含该组全部锚点的 chunk。多组题必须组组到齐，只召回一半证据不算答对 |
| MRR | 「最后一组证据到齐」的那个位次的倒数 |
| preview@1 | 第 1 条 chunk 的**前 120 字**里是否含全部锚点——就是 `verify_import.py` 打印 `topPreview` 的口径 |
| top1=答案 | 第 1 条 chunk 是否覆盖全部（非 judgment）gold 组 |
| 超范围题 | **不做命中判定**。检索接口没有拒答能力，只量分数是否与可答题可分 |
| judgment 组 | 我（作者）裁定的跨源关联，不是语料里的直接事实，不进头部指标，单独统计 |

题集分布：专业目录 8、薪资统计 8、职业大典 7、跨源综合 3、超范围 7。

## 二、三通道结果（同一套题、同一个库）

| 通道 | 命中@1 | 命中@3 | 命中@5 | 命中@10 | MRR | preview@1 | top1=答案 | 耗时 |
|---|---|---|---|---|---|---|---|---|
| **混合（RRF，现役配置）** | **16/26 = 61.5%** | 18/26 = 69.2% | 21/26 = 80.8% | 26/26 = 100% | **0.700** | 5/24 = 20.8% | 15/24 = 62.5% | 3.8 s |
| 纯向量 | 12/26 = 46.2% | 16/26 = 61.5% | 18/26 = 69.2% | 23/26 = 88.5% | 0.563 | 4/24 = 16.7% | 12/24 = 50.0% | 3.4 s |
| 纯关键词（FTS5 二元组） | 17/26 = **65.4%** | 21/26 = **80.8%** | 23/26 = 88.5% | 25/26 = 96.2% | **0.759** | 3/24 = 12.5% | 16/24 = 66.7% | 1.5 s |

三点必须一起读：

1. **前 10 条一定找得到证据**（100%）。也就是说这批语料「召不回来」不是主要矛盾。
2. **位次很不稳**：@1 只有 61.5%，@3 才 69.2%——中间 5~10 名挤着一堆几乎同分的 chunk
   （目标 chunk RRF 0.016314，第 10 名 0.013888，全在 0.0164 的满分线下面挤着）。
3. **关键词通道单独跑比混合更好**（@1 65.4% vs 61.5%、MRR 0.759 vs 0.700）。
   本题集偏字面事实（专业代码、表格数值、职业编码），关键词天然占优；
   混合里向量的 0.7 权重把精度拉低了。**这不能外推成「向量没用」**——同一份语料在
   语义型问题上向量才有优势，而本题集没有覆盖那一类，需要另出一套偏语义的题才能下这个结论。

## 四、弱项在哪（都是可复现的具体现象）

1. **数值型问题位次差**：CN12（行业最高 248752）第 9、CN13（住宿餐饮 62461）第 8、
   CN10 第 5、CN15 第 4。原因是统计局页面按行排版被抽成「行业名 / 2025 / 2024 / 增长率」
   竖直串，一张表横跨多个 512 字 chunk，数字和行业名经常落在**相邻但不相同**的块里。
2. **长异体专业名难排**：CN05（100709TK 药物经济与管理）第 7。同门类里同类格式的
   记录（例如 100102TK）在向量上几乎无法区分——每个 chunk 58% 是同一段出处样板。
3. **大典里的长定义段**：CN22（战略规划与管理工程技术人员）第 7。定义与任务列表被
   切成多块，问题里的短名称在这类长段落里权重被稀释。
4. **跨源语义桥接基本失效**：CN25/CN26 的 judgment 组（「低空专业 ↔ 无人机驾驶员」、
   「信息传输行业 ↔ 人工智能训练师」）在 top-10 里**一次都没被召回**。
   这和 `knowledge/evaluations` 里「跨语言瓶颈是术语而非召回」是同一类问题：
   语料里没有的映射关系，检索层不可能凭空造出来。

## 五、超范围题：检索层分不出来（重要）

| 组 | top-1 RRF 分 |
|---|---|
| 7 道超范围题 | min 0.016314 / 中位 0.016393 / max 0.016393（0.016393 = 两通道都排第 1 的满分） |
| 26 道可答题 | min 0.015186 / p25 0.016010 / 中位 0.016276 / max 0.016393 |

**7 道超范围题里 7 道的 top-1 分都 ≥ 可答题的 p25**，也就是「按分数设阈值」这一招
在这批语料上 100% 失效。典型例子：CN28「哪些高校开设了低空经济与管理、录取分数线是多少」
的 top-1 就是那条 `020110TK 低空经济与管理` 记录。

结论（口径提醒）：**拒答只能由上层 agent 依据「召回的正文里有没有答案」来判断，
不能在检索层用分数阈值断言。** 本报告不报「拒答正确率」，因为检索层没有这个能力。

## 七、结论与建议（按性价比排序）

1. **`import_weknora.py` 没有幂等保护**：`nbs-wages-2025.md` 被导入两次（36+36 个 chunk、
   `content_hash` 序列完全一致）。影响面：同内容两份副本各占候选位。
   建议加「同名已存在则拒绝/替换」的闸门；是否删掉重复文档需要业主点头（会作废
   `evidence/import-verify.json` 的 6 份文档口径）。
2. **chunk 粒度**：结构化目录 850 条记录挤进 287 个 chunk（3 条/chunk），
   58% 的字是同一段出处样板。建议改成「一条记录一个 chunk + 精简出处行」并重新导入，
   预期直接改善 @1 与 preview@1；代价是要重跑 `verify_import.py` 并同步相关文档口径。
3. **补一套偏语义的题**：本套题偏字面，导致「关键词单独跑比混合好」这个观察不能外推。
   要判断 RRF 的 0.7/0.3 权重是否适合这批语料，需要一套用同义改写、不含专有代码/数值的题。
4. **拒答能力不在检索层**：若产品要支持「资料不足就说不知道」，必须在 agent 层做，
   并且用「召回正文是否含答案」而不是分数阈值来判。

## 八、复算方式

```bash
# 1) 标注门禁（31 个 gold 组必须全部在真实库里找到出处）
python knowledge-cn/eval/verify_questions.py \
  --db knowledge-v1/weknora-src/data/weknora-cn.db \
  --questions knowledge-cn/evaluations/questions-cn-v1.json \
  --out knowledge-cn/evidence/questions-verified.json

# 2) 三通道检索评测
python knowledge-cn/eval/retrieval_quality.py \
  --kb aacc4889-a347-44ea-9dd1-b60ec1917cbb \
  --questions knowledge-cn/evaluations/questions-cn-v1.json \
  --top 10 --out knowledge-cn/evidence/retrieval-quality-20261001.json
```

## 九、未做项（不得省略）

- 没有人工（业主）逐题复核 gold；gold 是作者标注 + 机器复核出处，两层都不是人工判定相关性的口径。
- 没有做「引用支持度 / 回答质量」评测（要调模型，属上层）。
- 没有做跨切块参数（512 vs 其他）的对照实验。
- 没有做语义改写题集，因此权重结论未定。
